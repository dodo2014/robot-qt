## 三、坐标系与变换模型

### 3.1 两个坐标系

| 坐标系 | 轴定义                    | 原点                         |
| :-- | :--------------------- | :------------------------- |
| 基座系 | X 前 / Y 左 / Z 上        | **J1 回转轴心**与基座 Z = 0 平面的交点 |
| 相机系 | X 右 / Y 后 / Z 下（沿光轴向下） | 相机光心                       |

⚠ 基座原点不是含糊的「基座中心」——`Kinematics::Forward` 的 `x = l1·cos(j1) + l2_eff·cos(j1+j2)`（`src/Core/Kinematics.cpp:68-69`）即以 J1 回转轴心为原点。

### 3.2 旋转块 R —— 安装朝向常量，**不需要标定**

R 的三列就是相机三轴在基座系下的方向余弦：`X_c = −Y_b`、`Y_c = −X_b`、`Z_c = −Z_b`。

```
      ⎡  0  −1   0 ⎤
R =   ⎢ −1   0   0 ⎥        det(R) = +1   （是 180° 旋转，不是镜像）
      ⎣  0   0  −1 ⎦
```

`det(R) = +1` 说明它是刚体旋转而非反射，满足齐次变换要求。它与参考项目 `robot-single-thread/src/core/trans.py` 的 `camera_rotation` 逐元素一致，但**那只是旁证**——两机安装姿态未必相同，以本机实测为准。

⚠ **用户已做的方向验证覆盖 R 的第 0、1 行（XY 块）**：把夹爪尖端向前移动 → 画面上移、向左移动 → 画面左移，与 R 一致。**第 2 行（`Z_c = −Z_b`）未被该实测覆盖**，它由「相机朝下安装」这一物理前提直接给出；若相机光轴不竖直，靠 §七 残差判据兜。

### 3.3 平移块 t —— 唯一的未知量

`t = (Ox, Oy, Oz)` 是**相机光心在基座系中的位置矢量**（基座原点 → 相机光心），符号**以基座系为准**：

| 分量   | 定义                                   | 符号        |
| :--- | :----------------------------------- | :-------- |
| `Ox` | 相机光心相对 J1 回转轴心的**前后**偏移              | 相机在轴心前方为正 |
| `Oy` | 相机光心相对 J1 回转轴心的**左右**偏移              | 相机在轴心左侧为正 |
| `Oz` | 相机光心到**基座 Z = 0 平面（桌面）**&#x7684;垂直距离 | 恒为正       |

`P_base = R · P_cam + t` 展开：

```
base_x = Ox − y_c
base_y = Oy − x_c
base_z = Oz − z_c
```

⚠ **`Oz` 不是「回零后相机中心比 J1 中心高出的值」**——那是两个几何特征的间距，只有在 J1 中心恰好位于桌面高度时才数值相等。`Oz` 的参考面由 TR-031 真机实测钉死为桌面。  
⚠ 不要与 `tcpCalibration.toolOffsetX/Y/Z`（夹爪 TCP，`53 / 0 / −130 mm`）混称——建议文档与 UI 中把这组统一叫「手眼平移」。

### 3.4 完整 4×4 与配置落点

```
⎡  0  −1   0   Ox ⎤
⎢ −1   0   0   Oy ⎥
⎢  0   0  −1   Oz ⎥
⎣  0   0   0    1 ⎦
```

写进 `config/config.json`（**row-major**，16 个元素）：

```json
"tcpCalibration": {
  "handEyeMatrix": [0, -1, 0, Ox, -1, 0, 0, Oy, 0, 0, -1, Oz, 0, 0, 0, 1],
  "toolOffsetX": 53.0,
  "toolOffsetY": 0.0,
  "toolOffsetZ": -130.0
}
```

## 四、标定方法

### 4.1 方法 A：直接量取（兜底，粗）

不采点，只用卷尺量三个数。**适用于算法未交付、需要先跑通流程的阶段**。

| 步骤 | 做法                                                    |
| :- | :---------------------------------------------------- |
| 1  | 量 J1 回转轴心 → 相机光心的水平投影距离，按基座系取符号（前 + / 左 +）⇒ `Ox`、`Oy` |
| 2  | 量相机光心 → **桌面**的垂直距离 ⇒ `Oz`                            |
| 3  | 按 §3.4 填矩阵、重启，用 §七 的交叉验证项复核                           |

**局限**：`d2cAlign = "SW"` 下深度值源自深度模组、颜色像素源自 RGB 模组，**两者不共光心**（存在固定基线）；量到外壳会带进基线量级的不确定度。仅作兜底。

### 4.2 方法 B：点对反推（推荐）

由 §3.3 的三式直接反解，**不依赖卷尺、不依赖模组基线位置，且与机器人自己的 Z 参考面天然自洽**（即使 `z0/h1` 有残余误差，机器人信的就是它）。

| 步骤 | 做法                                                                                                                           |
| :- | :--------------------------------------------------------------------------------------------------------------------------- |
| 1  | **靶标 = 夹爪尖端**。这是唯一「真值不依赖标定」的靶——尖端基座坐标由关节角 + 已知 TCP 直接算出，不经视觉。为使算法能检出，在尖端贴一小块高对比色标，**色标中心与尖端重合**（不重合则须记录色标中心相对尖端的固定偏移并在解算时扣除） |
| 2  | 点动把尖端移到工作区内 ≥ 3 个位置，**建议 9 点**（3×3：覆盖内孔侧 / 中间 / 外径侧，并跨四个象限）                                                                  |
| 3  | 每个位置：**停稳后**读界面显示的尖端位姿 `(x_b, y_b, z_b)`（单位 mm）；同时从视觉检测页「检测结果」表读该靶的相机系读数 `(x_c, y_c, z_c)`                                   |
| 4  | 逐点解：`Ox = x_b + y_c`、`Oy = y_b + x_c`、`Oz = z_b + z_c`                                                                       |
| 5  | 取 9 个估计的**中位数**（抗离群）作为最终 `t`，代入 §七 算残差                                                                                       |

⚠ 步骤 3 的位姿与视觉读数是**同一静止时刻**的两个观测——读数期间臂不得移动。视觉页开连续检测即可。

**替代做法（算法未交付时）**：视觉页「检测结果」表同时给出 `U` / `V` / `Z` 三列，可用**真实内参**离线换算 `x_c = (U − cx)/fx · Z`、`y_c = (V − cy)/fy · Z`，避开 `SimAlgo` 的假内参。前提是真实内参已可获取（见 §五 前置项 1）。

### 4.3 方法 C：全量拟合（残差超差时升级）

若 §七 判据显示残差与「离光轴距离」呈线性相关（即有倾角），则放开 R：用 4×4 的 12 个未知量（旋转 9 + 平移 3）对 ≥ 6 个点做最小二乘，正交化后取最近的旋转矩阵。**本方案先按方法 B 走**——R 由安装朝向写死是用户的诉求（避免标定针），只有在残差证伪时才升级。

### 前置项 1 详述：为什么内参未定则标定无意义

识别分支直接取 `PuffResult.x/y/z`：

```
src/Logic/SequenceWorker.cpp:1035
    Pose robot = impl_->coord.CameraToRobot(best.x, best.y, best.z);
```

而唯一的算法实现 `SimAlgo` 用**硬编码假内参**：

```
src/HAL/algorithm/SimAlgo.cpp:53-56
    const double cx = w * 0.5;
    const double cy = h * 0.5;
    const double fx = 520.0;
    const double fy = 520.0;
src/HAL/algorithm/SimAlgo.cpp:142-143
    res.x = (res.pixelU - cx) / fx * z;
    res.y = (res.pixelV - cy) / fy * z;
```

`x/y` 与像素偏移成**比例**关系，比例系数是 `1/fx`。真机上真实 `fx` 与 `520.0` 不相等 ⇒ `x/y` 带一个**乘性误差**，而 `t` 是加性常数，**任何 `t` 都吸收不掉它**。量级：`z_c = 500 mm`、离主点 300 px 时，`fx = 520` 与 `fx = 800` 给出的横向坐标差约 `100 mm` 量级——远超抓取可接受误差。

两条出路：

| 出路      | 内容                                                                                                                                   | 代价                                                                                                      |
| :------ | :----------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| ① ~~等算法交付~~ **已失效** | 原为「在算法同事的交付约定里锁定 `PuffResult.x/y/z` 用哪组内参、以哪个物理点为原点」——**2026-10-12 17:20 用户裁定算法改由我方自研** ⇒ 该出路不存在，内参口径由我方自定（见 `algorithm_config_plan.md` §四） | —                                                                                                      |
| ② 提前标定（**现行唯一出路**） | 把真实内参接进识别链路（改动清单见 §5.1）——⚠ **不是**在启动时喂入，原因见 C3 | 需改代码（`ICamera::GetIntrinsics()` 与 `PixelToRobot` 都已存在，只是无调用者），属 `camera_integration_plan.md` 的「标定待实现」范围 |

⚠ 无论走哪条，**标定所用内参必须与运行期所用内参是同一组**，否则标定结果只在主点附近成立。

**算例**（示例值，仅示范算式）：设某点界面读数 `x_b = 311.58 mm`、`y_b = −177.70 mm`、`z_b = 165.00 mm`，同刻视觉读数 `x_c = −12.40 mm`、`y_c = −48.60 mm`、`z_c = 352.30 mm`，则

```
Ox = 311.58 + (−48.60) = 262.98 mm
Oy = −177.70 + (−12.40) = −190.10 mm
Oz = 165.00 + 352.30 = 517.30 mm
```

`Oz = 517.30 mm` 这个量级即「相机光心离桌面约半米」——与 §3.3 的定义自洽；若算出的 `Oz` 落在几十 mm 量级，说明参考面取错了。

## 七、残差判据与验收标准

| 项     | 判据                                         | 超差处置                            |
| :---- | :----------------------------------------- | :------------------------------ |
| XY 残差 | 各点 ≤ 1.0 mm                                | 优先怀疑内参不符（§五 前置项 1），其次靶点采集抖动     |
| Z 残差  | 各点 ≤ 2.0 mm                                | 检查深度有效性、相机倾角                    |
| 残差趋势  | 与「离光轴距离」**无线性相关**                          | 有相关 ⇒ 存在倾角，斜率 ≈ `tan θ` ⇒ 走方法 C |
| 重复性   | 同一位置连续 3 次读数，`x_c / y_c` 极差 ≤ 0.5 mm       | 检查相机固定刚度                        |
| 交叉验证  | 用解出的矩阵，令夹爪尖端移到 **2 个未参与解算**的位置，比对视觉报出的基座坐标 | 偏差超差 ⇒ 重新采集                     |

## 八、落地步骤

1. 填 `config/config.json` 的 `tcpCalibration.handEyeMatrix`（§3.4 的 16 个 row-major 数）。
2. **重启程序**——直接编辑文件不即时生效（§二）。
3. 核对启动日志出现 `[CoordTransform] Hand-eye matrix set (4x4)`（`src/Core/CoordTransform.cpp:22`）。若出现 `Hand-eye matrix not set, returning camera coords unchanged`（`src/Core/CoordTransform.cpp:34`），说明数组长度 ≠ 16 或键路径写错。
4. 跑一次「识别」动作，核对日志 `[SequenceWorker] Vision target: cam(x,y,z) → robot(x,y,z)`（`src/Logic/SequenceWorker.cpp:1041`），确认换算链路用的是新矩阵。
5. 跑「视觉引导」动作，核对构造的两段路径点：`pt1 = (x, y, z + offsetZ, guideR)`、`pt2 = (x, y, z, guideR)`（`offsetZ` 现行「引导抓取」节点用 `20.0 mm`，`guideR = 179.9°`）。
6. 真机抓取落点复测（重复定位精度）。

⚠ 步骤 1 的替代入口：`handEyeMatrix` **没有 UI 编辑入口**（§二）。若标定成为高频动作，可考虑补一个 `ConfigPage` 入口——**当前不做**，本方案按改文件 + 重启执行。
