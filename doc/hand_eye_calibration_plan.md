## 三、坐标系与变换模型

### 3.1 两个坐标系

| 坐标系 | 轴定义                    | 原点                         |
| :-- | :--------------------- | :------------------------- |
| 基座系 | X 前 / Y 左 / Z 上        | **J1 回转轴心**与基座 Z = 0 平面的交点 |
| 相机系 | X 右 / Y 后 / Z 下（沿光轴向下） | 相机光心                       |

⚠ 基座原点不是含糊的「基座中心」——`Kinematics::Forward` 的 `x = l1·cos(j1) + l2_eff·cos(j1+j2)`（`src/Core/Kinematics.cpp:68-69`）即以 J1 回转轴心为原点。

### 3.2 旋转块 R —— 安装朝向常量，**不需要标定**

R 的三列就是相机三轴在基座系下的方向余弦：`X_c = −Y_b`、`Y_c = −X_b`、`Z_c = −Z_b`。

```
      ⎡  0  −1   0 ⎤
R =   ⎢ −1   0   0 ⎥        det(R) = +1   （是 180° 旋转，不是镜像）
      ⎣  0   0  −1 ⎦
```

`det(R) = +1` 说明它是刚体旋转而非反射，满足齐次变换要求。它与参考项目 `robot-single-thread/src/core/trans.py` 的 `camera_rotation` 逐元素一致，但**那只是旁证**——两机安装姿态未必相同，以本机实测为准。

⚠ **用户已做的方向验证覆盖 R 的第 0、1 行（XY 块）**：把夹爪尖端向前移动 → 画面上移、向左移动 → 画面左移，与 R 一致。**第 2 行（`Z_c = −Z_b`）未被该实测覆盖**，它由「相机朝下安装」这一物理前提直接给出；若相机光轴不竖直，靠 §七 残差判据兜（残差定义与算式见 §6.2）。

### 3.3 平移块 t —— 唯一的未知量

`t = (Ox, Oy, Oz)` 是**相机光心在基座系中的位置矢量**（基座原点 → 相机光心），符号**以基座系为准**：

| 分量   | 定义                                   | 符号        |
| :--- | :----------------------------------- | :-------- |
| `Ox` | 相机光心相对 J1 回转轴心的**前后**偏移              | 相机在轴心前方为正 |
| `Oy` | 相机光心相对 J1 回转轴心的**左右**偏移              | 相机在轴心左侧为正 |
| `Oz` | 相机光心到**基座 Z = 0 平面**（机器人底座所坐落的地面）的垂直距离 | 恒为正       |

`P_base = R · P_cam + t` 展开：

```
base_x = Ox − y_c
base_y = Oy − x_c
base_z = Oz − z_c
```

⚠ **`Oz` 不是「回零后相机中心比 J1 中心高出的值」**——那是两个几何特征的间距，只有在 J1 中心恰好位于基座 Z = 0 平面时才数值相等。`Oz` 的参考面由 TR-031 真机实测钉死为该平面（= 机器人底座所坐落的地面）。  
⚠ **不要对 `z0 = 470` 做折算**：`z0` 与 `Pose.z` **同基准**，量 `Oz` 直接从同一个面量到相机光心即可（详见 §二 末注）。  
**免卷尺自检**：先 `Go −165` 让夹爪尖端落到 `Pose.z = 0`（界面读数 `0.0 mm`），再量「该尖端所在平面 → 相机光心」的垂直距离，即 `Oz`——用机器人自己的读数当尺子，不引入第二个基准。  
⚠ 不要与 `tcpCalibration.toolOffsetX/Y/Z`（夹爪 TCP，`53 / 0 / −130 mm`）混称——建议文档与 UI 中把这组统一叫「手眼平移」。

### 3.4 完整 4×4 与配置落点

```
⎡  0  −1   0   Ox ⎤
⎢ −1   0   0   Oy ⎥
⎢  0   0  −1   Oz ⎥
⎣  0   0   0    1 ⎦
```

写进 `config/config.json`（**row-major**，16 个元素）：

```json
"tcpCalibration": {
  "handEyeMatrix": [0, -1, 0, Ox, -1, 0, 0, Oy, 0, 0, -1, Oz, 0, 0, 0, 1],
  "toolOffsetX": 53.0,
  "toolOffsetY": 0.0,
  "toolOffsetZ": -130.0
}
```

## 四、标定方法

### 4.1 方法 A：直接量取（兜底，粗）

不采点，只用卷尺量三个数。**适用于算法未交付、需要先跑通流程的阶段**。

| 步骤 | 做法                                                    |
| :- | :---------------------------------------------------- |
| 1  | 量 J1 回转轴心 → 相机光心的水平投影距离，按基座系取符号（前 + / 左 +）⇒ `Ox`、`Oy` |
| 2  | 量相机光心 → **基座 Z = 0 平面（机器人底座所坐落的地面）** 的垂直距离 ⇒ `Oz`                            |
| 3  | 按 §3.4 填矩阵、重启，用 §七 的交叉验证项复核                           |

**局限**：`d2cAlign = "SW"` 下深度值源自深度模组、颜色像素源自 RGB 模组，**两者不共光心**（存在固定基线）；量到外壳会带进基线量级的不确定度。仅作兜底。

### 4.2 方法 B：点对反推（推荐）

由 §3.3 的三式直接反解，**不依赖卷尺、不依赖模组基线位置，且与机器人自己的 Z 参考面天然自洽**（即使 `z0/h1` 有残余误差，机器人信的就是它）。

| 步骤 | 做法                                                                                                                           |
| :- | :--------------------------------------------------------------------------------------------------------------------------- |
| 1  | **靶标 = 夹爪尖端**。这是唯一「真值不依赖标定」的靶——尖端基座坐标由关节角 + 已知 TCP 直接算出，不经视觉。为使算法能检出，在尖端贴一小块高对比色标，**色标中心与尖端重合**（不重合则须记录色标中心相对尖端的固定偏移并在解算时扣除） |
| 2  | 点动把尖端移到工作区内 ≥ 3 个位置，**建议 9 点**（3×3：覆盖内孔侧 / 中间 / 外径侧，并跨四个象限）                                                                  |
| 3  | 每个位置：**停稳后**读界面显示的尖端位姿 `(x_b, y_b, z_b)`（单位 mm）；同时从日志行 `[SequenceWorker] Vision calib: pixel(u,v) depth=… intr(fx,fy,cx,cy)`（`src/Logic/SequenceWorker.cpp:1071`）读该靶的像素 `u/v`、深度 `depth` 与**本次实际使用的内参**，按 `x_c = (u − cx)·depth/fx`、`y_c = (v − cy)·depth/fy`、`z_c = depth` 换算出相机系读数 |
| 4  | 逐点解：`Ox = x_b + y_c`、`Oy = y_b + x_c`、`Oz = z_b + z_c`                                                                       |
| 5  | 取 9 个估计的**中位数**（抗离群）作为最终 `t`，代入 §七 算残差                                                                                       |

⚠ 步骤 3 的位姿与视觉读数是**同一静止时刻**的两个观测——读数期间臂不得移动。视觉页开连续检测即可。

**取数来源（2026-10-13 起）**：`Vision calib:` 行给出的是**反投影的全部原始量**（像素 + 实际参与换算的内参 + 深度），因此 `x_c / y_c / z_c` 由它**离线复算**即可——这是 §5.1 C1b 的用途，也是「标定所用内参 = 运行期内参」这条判据的落地方式（两组数来自同一个 `camera->GetIntrinsics()`）。

**替代来源**：视觉检测页「检测结果」表同时给出 `U` / `V` / `Z` 三列，同样可换算，但**不带内参** ⇒ 还须另找真实 `fx/fy/cx/cy`（见 §五 前置项 1，现由 `[OrbbecCamera] 彩色内参: …` 一行给出）。

### 4.3 方法 C：全量拟合（残差超差时升级）

若 §七 判据显示残差与「离光轴距离」呈线性相关（即有倾角；带符号残差对 `r` 做线性回归的具体做法见 §七），则放开 R：用 4×4 的 12 个未知量（旋转 9 + 平移 3）对 ≥ 6 个点做最小二乘，正交化后取最近的旋转矩阵。⚠ 方法 C 与 §6.2 的口径 1 不同——**那里才有真正的最小二乘**（本方案方法 B 取中位数、不拟合），且需 ≥ 6 点才使 12 个未知量可解。**本方案先按方法 B 走**——R 由安装朝向写死是用户的诉求（避免标定针），只有在残差证伪时才升级。

### 前置项 1 详述：为什么内参未定则标定无意义

识别分支直接取 `PuffResult.x/y/z`：

```
src/Logic/SequenceWorker.cpp:1035
    Pose robot = impl_->coord.CameraToRobot(best.x, best.y, best.z);
```

而唯一的算法实现 `SimAlgo` 用**硬编码假内参**：

```
src/HAL/algorithm/SimAlgo.cpp:53-56
    const double cx = w * 0.5;
    const double cy = h * 0.5;
    const double fx = 520.0;
    const double fy = 520.0;
src/HAL/algorithm/SimAlgo.cpp:142-143
    res.x = (res.pixelU - cx) / fx * z;
    res.y = (res.pixelV - cy) / fy * z;
```

`x/y` 与像素偏移成**比例**关系，比例系数是 `1/fx`。真机上真实 `fx` 与 `520.0` 不相等 ⇒ `x/y` 带一个**乘性误差**，而 `t` 是加性常数，**任何 `t` 都吸收不掉它**。量级：`z_c = 500 mm`、离主点 300 px 时，`fx = 520` 与 `fx = 800` 给出的横向坐标差约 `100 mm` 量级——远超抓取可接受误差。

**实测（2026-10-13，C2 落地后首条日志）**：本机 Gemini 336（SN `CP9KB530005S`）在 `1920×1080` 下

```
[OrbbecCamera] 彩色内参: fx=1037.46 fy=1037.70 cx=966.17 cy=542.81 dist(k1=0.00998 k2=-0.05192 p1=-0.00052 p2=-0.00033) 1920x1080
```

即 `fx_real / fx_sim = 1037.46 / 520.0 ≈ 2.00`——**假内参把 `x/y` 压到真实值的约一半**。逐点量级（`z_c = 500 mm`）：

| 像素列 `u`     | 正确 `x_c` / mm（`fx = 1037.46`） | 改造前 `x_c` / mm（`fx = 520`） | 偏差 / mm |
| :---------- | :-------------------------- | :----------------------- | :----- |
| 966（主点附近）   | −0.08                       | 5.77                     | 5.9    |
| 1166（偏 200 px） | 96.31                       | 198.08                   | 101.8  |
| 1266（偏 300 px） | 144.50                      | 294.23                   | 149.7  |
| 1466（偏 500 px） | 240.89                      | 486.54                   | 245.7  |

偏差随「离主点像素距离」线性增长、与 `t` 无关 ⇒ **前置项 1 不是理论风险，是本机实测到的 100~250 mm 级系统误差。**

**残差算式**（本表两列与 §七 判据的唯一定义）：

残差 = **「模型预测的基座坐标」与「界面实际读数」之差**，也等价于**该点自己反解出的 `t_i` 与最终采用值 `t` 之差**。两条观测链（机器人链 `x_b/y_b/z_b` 与视觉链 `x_c/y_c/z_c`）各自把同一个物理点表达了一遍，对不上多少就是残差。代入 §3.3 的三式化简：

```
Δx_b = x_b − (Ox − y_c) = (x_b + y_c) − Ox = Ox_i − Ox
Δy_b = y_b − (Oy − x_c) = (y_b + x_c) − Oy = Oy_i − Oy
Δz_b = z_b − (Oz − z_c) = (z_b + z_c) − Oz = Oz_i − Oz

XY 残差_i = √(Δx_b² + Δy_b²) = √((Ox_i − Ox)² + (Oy_i − Oy)²)
Z  残差_i = |Δz_b|            = |Oz_i − Oz|
```

⇒ **填表不必重算预测坐标**：本表前五列已经给出 `Ox_i / Oy_i / Oz_i`，两列残差只需各自减去「中位数」行即可。

**解算算例**（单点，仅示范 `t` 的算式）：设某点界面读数 `x_b = 311.58 mm`、`y_b = −177.70 mm`、`z_b = 165.00 mm`，同刻视觉读数 `x_c = −12.40 mm`、`y_c = −48.60 mm`、`z_c = 352.30 mm`，则

```
Ox = 311.58 + (−48.60) = 262.98 mm
Oy = −177.70 + (−12.40) = −190.10 mm
Oz = 165.00 + 352.30 = 517.30 mm
```

`Oz = 517.30 mm` 这个量级即「相机光心离桌面约半米」——与 §3.3 的定义自洽；若算出的 `Oz` 落在几十 mm 量级，说明参考面取错了。

**残差算例**（3 点，示范算式）：设 9 点采集中某 3 点的估计如下，最终采用值（9 点中位数）为 `t = (263.0, −190.0, 517.5) mm`：

| 点 | `Ox_i` / mm | `Oy_i` / mm | `Oz_i` / mm | XY 残差 / mm | Z 残差 / mm |
| :- | :---------- | :---------- | :---------- | :----------- | :---------- |
| 1 | 263.0       | −190.0      | 517.5       | 0.00         | 0.0         |
| 2 | 263.5       | −189.6      | 517.5       | 0.64         | 0.0         |
| 3 | 262.6       | −190.5      | 516.8       | 0.64         | 0.7         |

点 2：`√(0.5² + 0.4²) = 0.64 mm`；点 3：`√((−0.4)² + (−0.5)²) = 0.64 mm`。三点均在 §七 判据内 ⇒ 判合格。点 1 恰是三个分量的共同中位点，故两轴残差均为 0——见下第 2 条口径。

**三条口径**（判读 §七 前必读）：

1. **残差衡量自洽性，不衡量精度。** 模型对 `t` 是线性的、每点独立给出一组完整估计 ⇒ 本方案**不存在最小二乘拟合**；`t` 取中位数，残差就是各点估计围绕中位数的离散度。任何**所有点共有**的误差都被 `t` 吸收、残差里看不见——例：深度值整体偏 +2 mm ⇒ 全部 `Oz_i` 同向平移 ⇒ 中位数跟着平移 ⇒ 残差一个都不变。**共模误差只能靠 §七 的交叉验证（2 个未参与解算的点）抓**，这正是该条存在的理由。
2. **中位数拟合 ⇒ 残差之和不为 0。** 若改用均值，Σ 残差恒为 0；取中位数则不是，且**每个分量至少有 1 个点的残差恰好为 0**（该分量的中位点，三个分量的中位点未必是同一个点）。残差为 0 不代表该点更准。
3. **§七 的 1.0 mm / 2.0 mm 是「一致性合格」门槛，不等于抓取落点精度 1 mm。**

## 七、残差判据与验收标准

| 项     | 判据                                         | 超差处置                            |
| :---- | :----------------------------------------- | :------------------------------ |
| XY 残差 | 各点 ≤ 1.0 mm                                | 优先怀疑内参不符（§五 前置项 1），其次靶点采集抖动     |
| Z 残差  | 各点 ≤ 2.0 mm                                | 检查深度有效性、相机倾角                    |
| 残差趋势  | 与「离光轴距离」**无线性相关**                          | 有相关 ⇒ 存在倾角，斜率 ≈ `tan θ` ⇒ 走方法 C |
| 重复性   | 同一位置连续 3 次读数，`x_c / y_c` 极差 ≤ 0.5 mm       | 检查相机固定刚度                        |
| 交叉验证  | 用解出的矩阵，令夹爪尖端移到 **2 个未参与解算**的位置，比对视觉报出的基座坐标 | 偏差超差 ⇒ 重新采集                     |

**残差与趋势的算法**：

- **残差算式**见 §6.2（`XY 残差_i = √((Ox_i − Ox)² + (Oy_i − Oy)²)`、`Z 残差_i = |Oz_i − Oz|`）。它衡量的是**自洽性**——任何所有点共有的误差（如深度整体偏置）都会被 `t` 吸收、残差里看不见 ⇒ 故本表另设「交叉验证」一条，共模误差只有留出点能抓。
- **趋势判据的算法**：横轴取离光轴距离 `r_i = √(x_c_i² + y_c_i²)`（mm），纵轴取**带符号**的逐分量残差 `ΔOx_i / ΔOy_i / ΔOz_i`，做一元线性回归，看斜率是否显著非零。倾角 θ 的定位误差 ≈ `r · tan θ` ⇒ **斜率 ≈ `tan θ`**（1° 在 `r = 500 mm` 处约 8.7 mm）。
- ⚠ **必须用带符号残差**。若把 `|残差|` 对 `|r|` 作图，倾角造成的误差在光轴两侧反号、折成 V 形，线性拟合的斜率接近 0 ⇒ 判据失效。应按 `x_c` / `y_c` 两个方向各回归一次，不要用绝对值。
- ⚠ **趋势非零 ≠ 倾角**。内参 `fx / fy` 不符（§五 前置项 1 的乘性误差）同样表现为「残差随离轴距离线性增长」——`x_c = (u − cx) · depth / fx` 本身就是离轴距离的函数。**区分看量级**：内参错 2 倍时 `r = 300 mm` 处偏差达 150 mm 量级（§五 实测表），而倾角 1° 在同样位置只有约 5 mm。故处置顺序为**先查内参、再看倾角**，与表中「XY 残差」行的处置列一致。
