## 八、P6 动作树与分组并发（TR-102，当日收口）

### 8.1 技术路线：为什么不用多线程

组内并发**不能用 `QtConcurrent`**，四条理由（方案 §四）：① `Impl::lastError` **无锁**，多线程会破坏其线程独占前提；② 线程归属会**脱离 `ShutdownWorker`** 的管理范围（退出时悬垂）；③ `InMainThread` 的阻塞往返会被放大 N 倍；④ 硬件层加锁覆盖不全，且 `Qt6::Concurrent` **未链接**。故定为**单线程协作式调度**：收益来源是**等待时间的重叠**，不是计算并行。

### 8.2 落地要点

- **数据模型**：`ActionData` 加 `NodeType nodeType`（`"action"` / `"group"`，**与 `ActionType` 正交、不进枚举**）与 `QVector<ActionData> children`（**不允许嵌套**）；`SchemeData::actions` → **`nodes`**，`load()` 先读 `nodes` 再回落旧键 `actions`。
- **加载升级**：`normalizeActionIds()` 扩为**全树**处理——先**扁平化非法嵌套**（日志 `Group 'X' had nested group(s): flattened N child node(s) -> M`），再对全树做编号唯一 / 非正 / 重复补发，最后抬高 `nextActionId`。**升级仍惰性**（只加载不编辑不写盘）。
- **校验（按资源不按类型）**：`resourceKeysOf(ActionType)` 返回资源集合——`Move` **与 `VisionGuide` 共用四轴**（漏这条会放过「引导 + 移动」同组）、`Gripper` → `Axis_Gripper`、`Extrude` → `Axis_Extruder`、`Vision` → `Camera`、`Delay` → **空集**（多个延时同组**合法**，§6.3）。`validateGroupChildren()` 依次做**嵌套 → 数据依赖 → 资源两两求交**三类拦截。
- **UI**：`QListWidget` → `QTreeWidget`、`currentRowChanged` → `currentItemChanged`、`m_currentActionIdx`（43 处）→ `m_currentNodeId`（节点编号）；分组条目 `#N 〔分组〕 名称（M 个子动作）`；新增「新建分组」按钮与**分组详情页**（stack 索引 7）；`OnNewAction` 按落点（分组内 / 组内子节点之后 / 一级之后）插入 + 冲突类型**置灰**（`QStandardItemModel` flags + tooltip），确认前再对**试算副本**跑一次 `validateGroupChildren`；`OnMoveActionUp/Down` 限定**同级移动**；`RefreshGuideSourceCombo` 改**全树扫描**（否则组内的识别动作无法被视觉引导引用）。
- **执行层**：`ExecuteNode` 插在 `ExecuteOnce` 与 `ExecuteAction` 之间（按 `nodeType` 分派）；6 类动作由阻塞式改**可步进状态机**（`RunnerState` + `StepRunner`，统一归约为「段序列」Begin → Dispatch → Wait → 下一段）；新增 `RunScheduler`（**20 ms tick，与改造前 `WaitForAxes` 同节拍**）。
- **§Q2 停止语义**：`stopAndWaitAll` —— 停止 / 内部失败**先安全停下全部子动作再返回**，最长等 3000 ms 后 WARN `group stop: axes still busy after 3000 ms`。提前返回会让硬件仍在运动时退出执行循环。
- **暂停**：**整组减速停** + 汇合后统一挂起 + 恢复统一重发当前段；`Delay` 按 `pauseAccumMs` **冻结计时**（10 s 延时跑到第 8 s 被暂停，恢复后只应再等约 2 s）。

### 8.3 两处关键判断

1. **刻意偏离方案 §十第二步**：原文写「分组此时按『顺序执行其子节点』处理」，实际实现是**单动作与分组共用同一个 `RunScheduler`**（单动作即 1 元素 `runners`）。理由：分组若真按顺序执行状态机，会**阻塞调度器**，把第三步要拿的「等待重叠」收益整个丢掉；共用同一实现也让暂停 / 停止 / 续走只有**一份语义**。
2. **内部中止与用户停止分流**：调度器用独立的 `aborting` 标记区分「子动作失败」与 `cancel`（用户停止 / 急停）——置 `cancel` 会把动作失败**误报成「用户停止」**。`lastError` 只承载首个失败原因（**失败归因 = 首个失败者**）；子树内**未新增任何 `errorOccurred` emit**（D17 单点化保持）。
