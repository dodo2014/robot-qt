### TR-076 单步执行失效（回归缺陷；09-08 真机 8.13 发现，09-09 修复并复测通过）

- **现象**：工艺页点「单步执行」应只跑 1 个动作后挂起在「● 单步暂停」（N 个动作需 N+1 次点击）；实测点一次跑完全部动作，状态「运行中」→「✅ 完成」，全程无暂停、单步按钮不可点。
- **根因（自伤回归）**：09-07 为修 TR-074 隐患 1 给 `RunSequence` 加了「入口清 `stepMode`」——而单步流程是 ProcessPage 先 `SetStepMode(true)` 再 `RunSequence`，标志刚设就被抹掉 → 单步退化为连续执行。
- **修复**：撤销入口清理，改为**会话结束统一清**（`StartExecution` 末尾 `safeSession/stepMode` 一并清）；`RunSingleAction` 保留入口清理（单动作与单步互斥）。`SequenceWorker.cpp` + `ProcessPage.cpp`。
- **复测**：8.13 通过——单步只跑第 1 个动作停「● 单步暂停」、N+1 次点击至「✅ 完成」均正常。

### TR-077 执行选中动作破坏单步会话（09-09 真机发现并修复）

- **现象**：单步跑完第 1 个动作停在「● 单步暂停」→ 选其它动作点「执行选中动作」→ 引擎拒绝（`RunSingleAction rejected: already running`）；**之后单步也被拒**（`Step mode ON → RunSequence rejected`）→ 会话死锁，只能停止。
- **修复**：单步/自动会话期间「执行选中动作」按钮**置灰**（UI 防呆）+ 引擎侧门禁兜底，杜绝死锁路径。
- **复测**：单步期间按钮置灰，单步可正常继续释放。

## 二、阶段 9（TR-074 全局安全位）真机推进 9.1–9.9

### TR-079 设备配置页示教安全位不同步 + 科学计数法（9.4 发现并修复）

- **根因**：`ConfigPage` 安全位控件只在**构造时**读一次 config，且该类**无 `showEvent`**；示教由 `ManualControlPage::OnTeachSafePos` 直接 `ConfigManager::set` 写入（按设计不 emit `paramsChanged`）→ 配置页无从感知，**重启才显示实际值**。
- **修复**：新增 `ConfigPage::RefreshSafePosFields()` + `showEvent` 重写（每次切到配置页重新读 config 回填；复选框用 `QSignalBlocker` 阻断 toggled 防反向写回；`setText` 不触发 `editingFinished` 故不误写）。
- **附带**：示教写入前量化到两位小数并消除 −0（原直接落盘全精度 double 产生 `j1: -4.6875000009549694e-05`，与提示文案对不上；该值不足 1 个脉冲、**对运动零影响**，仅为存档/显示一致）。
- **教训**：「config 现读现用 + 不 emit 信号」的设计下，所有展示该配置的页面**必须在页面显示时重新读取**，只靠构造初值必然产生"重启才对"的不同步。

### TR-080 回安全位误报「有任务执行中」（9.6 发现并修复）

- **现象**：重启 → 使能 → 一键回零 → 点「回安全位」提示「有任务执行中，无法回安全位」，**实际无轴在动**；日志三次复现 `MoveAbs rejected: axis N homing in progress` → `state -> 3 (Fault)`。
- **根因（三层叠加）**：① **舵机重复回零竞态**——`checkServoHomeDone` 清除 `homingActive_` 的分支有 `!axisHomed_[idx]` 条件，轴已回零过时重复回零走不到清除分支，只能等 5s busy 超时兜底；期间全轴 homed 上升沿自动触发回安全位，首条 `MoveAbs` 撞回零门禁被拒；② `ExecuteActions` 失败置 **Fault 锁存**（设计行为，但正常操作序列必然产出一次）；③ 手动页把 Fault 一律报成「有任务执行中」，且 `errorOccurred` 只连工艺页、`ClearFault` 唯一入口在自动页 → 手动页对 Fault 完全不可见。
- **修复**：① 删掉 `!axisHomed_[idx]` 条件与卡轴路径对齐（`MarkAxisHomed` 幂等、`homeStateChanged` 电平语义的三消费者均幂等，重复 emit 安全）→ 重复回零后 **≤250ms 解锁**；② `OnGoSafePos` 区分 Fault：红色提示「故障锁存，请到自动运行页点「↺ 清报警」」；Running/Paused 保持原文案；③ 补 `triggered/skipped` 成对日志。
- **教训**：`axisHomed_`（电平）与 `homingActive_`（过程）是两个独立状态数组，"全轴 homed" ≠ "回零过程全结束"——跨数组联动的上升沿触发必须考虑过程标志的滞留窗口。

### TR-081 上升沿语义澄清 + 急停恢复链改手动回安全位（9.9 发现）

- **触发**：9.9 场景（手动移走 → 一键回零）实测**未**自动回安全位；手动点则正常。
- **澄清**：自动回安全位用 `lastHomed_` **上升沿**判定，而 `axisHomed_` 仅在「启动初始化 / 回零被中断」时清除——手动移走、**急停**、断使能都不清 → 已回零状态下重回零**无上升沿**。设计文档本就明确此为**防误触发**设计（否则单轴回零会突然走安全位），**9.9 原用例文本"自动发起"系笔误**。
- **连带发现（更重要）**：急停恢复链原描述的"回零 → 自动回安全位"**不成立**（急停不清已回零轴 homed → 无上升沿）；此前文档未察觉，阶段 10 测到 10.16 必然踩坑。
- **决策（方案 A，零行为逻辑改动）**：接受现状，恢复链改为「使能 → 回零 → **手动**回安全位 → 切自动」；急停红字①文案同步修正（`ManualControlPage.cpp:176`，唯一代码改动）。**方案 B（急停清全轴 homed 使上升沿成立）否决**——急停语义扩张影响面大，手动一步可接受。
- **同步文档**：phase3 9.9/10.14/10.16/10.17、`global_safe_position.md` §五+概述、`architecture.md`、`auto_run_loop_production.md` 10.23。
- **一句话定论**：**自动回安全位 = 软件启动后的第一次一键回零**。
