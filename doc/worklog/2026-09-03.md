### 改动 2：单步执行中禁止切换/删除方案

用户要求（测试补 5 后提出）。提取 `IsExecutionActive()`（`m_stepActive || m_worker->IsRunning()`）供 `OnConfirmSwitch` 与 `OnDeleteScheme` 共用，执行期弹窗拒绝。

根因：`SequenceWorker` 跑的是启动时**值拷贝**的 scheme（`SequenceWorker.cpp:157`），切换/删除方案后继续点「单步执行」会按旧拷贝继续推进，与界面显示的方案不一致。

### 改动 3：D2 修复 —— 单步按钮执行期禁用（二次修复：同步禁用）

用户选择「执行期禁用按钮」而非「stepGo 改计数器」。

理由：改计数器后真机上狂点会连跑多个动作，反而更危险；禁用按钮既消除隐患，又给出更清晰的交互 —— **按钮亮起 = 轮到操作者点**。

**第一次修复（失败，仅信号驱动）**：`actionStarted` / `stateChanged("运行中")` → `setEnabled(false)`；`stateChanged("单步暂停")` → `setEnabled(true)`。真机补 1 仍复现：连点会跑两个动作、日志出现两条「释放下一步」。

**竞态根因**：禁用是**跨线程信号驱动（异步）**。`stateChanged("运行中")` 由 worker 线程 emit，经 queued 投递回主线程事件队列；而连点的第 2 个 QMouseEvent 已经在主线程队列里、**排在信号之前** → 处理点击时按钮尚未灰 → `NextStep()` 被再次接受 → `stepGo` 提前置位 → A1 跑完后 `WaitForStep` 立即放行连跑 A2。

**二次修复（同步禁用）**：在 `OnStepExecute` 内点击即 `setEnabled(false)`：
- 启动分支：`RunSequence` 成功后同步禁用
- NextStep 分支：`NextStep()` 成功后同步禁用
- 重新点亮仍由 `stateChanged("单步暂停")` 驱动

Qt 对 disabled 按钮不派发 `clicked`，第 2 下点击事件到达时按钮已灰 → 被拦截。

**顺带修 D1**：启动分支现在检查 `RunSequence` 返回值，被拒则 return 且**不置 `m_stepActive`**（原实现无条件置 true，被拒后会话永久卡死，所有后续点击走 NextStep 分支）。

### 三条与既有文档冲突的实测结论

1. **点击次数是 N+1，不是 N**（1 次启动 + N 次释放）。`WaitForStep` 在 for 循环体内（`SequenceWorker.cpp:306`），最后一个动作跑完也会挂起，须再点一次才发 `schemeFinished`。`real_machine_plan_phase2.md:116` 原写「N 次」已修正。

2. **「停止」不是就近刹车，会执行完当前动作才停**。`Stop()` 只置 cancel、不下发任何停轴命令（`SequenceWorker.cpp:210-215`）。`TR-040` 的「业务停止就近」表述与代码不符 —— 历史行保留不动，以新增记录为准。

3. **5.2 语义**：点一次 = 立即执行下一个动作 + 该动作执行完立刻挂起，不会自动连跑。用户追问后确认。
