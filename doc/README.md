# doc/ 文档索引

> **本文件是 `doc/` 的入口索引**——先读本文件，再决定打开哪一篇。新增、移动或归档文档后请同步更新本文件。
>
> **权威性声明**：本目录下任何文档都**不构成技术事实的权威源**。技术事实（架构、参数、行为、踩坑、流程规约）一律以 **`AGENTS.md` 与源码**为唯一权威源；本目录文档与二者冲突时，以 `AGENTS.md` 与源码为准，并请修正本目录文档。
>
> 表述规范（用词、术语、中英混排、语种分工）见 `doc_output_standards_guide.md`；测试台账见根目录 `TEST_RECORD.md`。

## 怎么用

1. **只打开状态为 🟢 / 🟡 / ⏳ 的文档**。⚠ / 📦 / ❌ 的文档仅在需要追溯历史时打开。
2. **大文档不要整篇读**——`auto_run_loop_production.md`（49KB）、`vision_test_page_redesign_plan.md`（34KB）按标题定位到具体小节即可。
3. 查「某项功能现在怎么实现」→ `architecture.md` + 源码；查「某项改动是否已验收」→ `TEST_RECORD.md`。

## 归档规则

**触发条件**：文档对应的功能已实施并验收，且其结论已沉淀进 `AGENTS.md`、`architecture.md` 或源码注释。

**操作步骤**：

1. **先沉淀**：把仍然生效的决策与踩坑挪进权威源（`AGENTS.md` 或对应现行文档），归档后历史文档不再需要被翻。
2. **整体移入** `doc/archive/`，**文件名不变**——只靠目录位置表达状态，不靠改名。
3. **加归档横幅**：在文件顶部写明「不要把它当权威源」+「结论已沉淀处」+「保留理由」。
4. **修引用**：全库 `grep` 该文件名，把路径改到新位置——**包括源码注释**（如 `src/Core/Kinematics.h`）。
5. **同步本文件**：更新「归档内容」表，并从上方方案表中移除。

## 维护约定

- 新增文档请在此登记，并如实填写状态；状态变化（如 🟡 → 🟢）时回来改。
- 发现文档内容与 `AGENTS.md` 或源码冲突时，**以 `AGENTS.md` 与源码为准**，按三级处理：
  1. **仍有有效内容** → 修正后保留；
  2. **仅剩历史价值** → 按「归档规则」移入 `doc/archive/`；
  3. **内容已被权威源完全覆盖、且存在错误值** → **直接删除**（先例：`机械臂参数.md` 于 2026-09-14 删除——其 L1 值错误，其余参数均已在 `config/config.json`，无信息损失）。
  不要留着让下一个 Agent 踩。
