# CreamPuffRobot 测试结果取证与回填

## 为什么需要这个 skill

用户报「12.15 通过」时，**「通过」的含金量是不一样的**：有的判据能从日志读出精确数值，
有的只有 UI 目视，还有的在仿真下**物理上不可能观测**。

若一律写成「🟢 通过」，这份文档就失去了作为证据的价值——几个月后没人能分辨
「真的验证过」和「当时看着像对」。本 skill 的产出必须让**每一条结论都带着它的取证等级**。

## 三档取证等级（回填时必须逐条标注）

| 等级 | 含义 | 判据长什么样 |
| --- | --- | --- |
| **日志实证** | 能从日志读到判据要求的**数值 / 事件序列** | Z 差 = offsetZ、`state -> 2 reason 1`、`Scheme finished` 仅 1 次 |
| **数据侧旁证** | 判据本身是 UI 目视，但**同批日志能验证其数据来源** | 只读预览显示的值 == 引擎算出的值（逐位一致） |
| **口述 / UI 目视** | 无可回溯痕迹 | 下拉框有占位项、控件置灰、颜色正确 |

⚠ **口述项必须显式写「口述通过（UI 目视）」**，并在块的末尾汇总一行「取证边界」，
把三档分别列清。**不要**把口述项写成和日志实证项一样的「🟢」。

## 步骤

### 1. 读判据

`doc/test/real_machine_plan_phase3.md` 的用例表（阶段 11~13）。**判据里的每个数值都要当成待验证项**，
不要只读个大意——例如「两段 Z 差恒 = offsetZ」要求的是**精确相等**。

### 2. 定位日志段

日志在**工程根** `log/creampuff_YYYY-MM-DD.log`（路径随 cwd，不是 exe 旁）。
先数会话边界，把日志切成「每次启动一段」：

```bash
grep -an "Initialize complete" log/creampuff_$(date +%Y-%m-%d).log | tail -6
# 每段从 HardwareManager.cpp:222 那行开始
```

### 3. 交叉取证（本仓库常用 grep 配方）

```bash
L=log/creampuff_2026-09-28.log
awk 'NR>=<段起始行>' "$L" | grep -a "<关键串>"
```

| 想看的 | 关键串 | 出处 |
| --- | --- | --- |
| 动作流 | `Node #N: <动作名>` | `SequenceWorker.cpp:661` |
| 页面流 | `worker: …` / `单步 actionStarted #N` / `actionFinished #N` | `ProcessPage.cpp:1198 / :1285 / :1292` |
| 状态机 | `state -> N reason M` | `SequenceWorker.cpp:479` |
| 暂停 / 续走 / 停止 | `pause requested` / `resume requested` / `immediate stop requested (decel stop, keep enabled)` | `:488 / :500 / :443` |
| IK 与示教 | `IK → J(j1, j2, z, r)` / `Teach joints → J(…)` / `IK failed for point` | `:1244 / :1247 / :1238` |
| 视觉识别 | `Vision target: cam(…) conf=… → robot(…) [node #N yaw=… ignored]` | `:1038` |
| 视觉引导 | `VisionGuide #N ← Vision #M: base(…) offsetZ=… r=…` | `:1131` |
| 执行失败 | `runner failed: node #N '<名>' — <原因>` | `:949 / :943` |
| 页面报错 | `执行出错: …` | `ProcessPage.cpp:1277` |

- **状态枚举**：`WorkerState { Idle=0, Running=1, Paused=2, Fault=3 }`；
  `PauseReason { None=0, User=1, Step=2 }`（`SequenceWorker.h`）。
- **`grep` 必须带 `-a`**，否则遇到 GBK 字节会判成二进制而停止输出。
- **时间戳对齐**：引擎日志与页面日志属同一批事件，通常相差 < 30 ms——可用它把
  「引擎算出的坐标」与「页面显示的文字」对起来（这是做「数据侧旁证」的关键）。

### 4. 行号可当版本指纹

改了 `.cpp` 之后，日志里的 `文件:行号` 会漂移。**用漂移反推当时跑的是哪个 exe**：

> 例：`SequenceWorker.cpp:1125` → `:1131` 的位移 = TR-119 的净增 6 行 ⇒ 11:06 起的运行已载入修复版。

改动量大时，这是唯一能事后证明「用户跑的是新 exe」的手段。

### 5. 回填

- **实测记录块** → `doc/test/real_machine_plan_phase3.md` 对应阶段（`> **实测记录（阶段 12B，…）**：`）。
  每例一行，格式：`> - **<编号> <★?> <图标>** —— **<取证等级>**：<证据> <结论符号>`。
- **`TEST_RECORD.md` 只在有「修复 / 新功能」时追加编号**（最大号 + 1，禁重排禁复用）。
  **纯测试执行结果不新增编号**——更新既有条目的「测试状态」列即可。
- 改完表格跑 `md-table-check` skill 复核列数。

### 6. 判据在 Sim 下不可判时 → 追加真机用例

不要把它留在 12B 里当「通过」，也不要删掉。**在 12C 追加新用例**（编号**追加末尾、不重排**），
然后在 12B 记录里写明「**已移交真机用例 12.xx**」，并在「⏳ 未执行」行注明**不计入 12B 的通过面**。

⚠ **追加用例要同步 5 处计数/范围**（漏一处就自相矛盾）：

| # | 位置 | 形态 |
| --- | --- | --- |
| 1 | 阶段标题下「**前置**」的档位说明 | `- **C 档（12.22~12.28）**：…` |
| 2 | 用例文档顶部**批次索引** | `单开 **阶段 12**（用例 12.1~12.28）` |
| 3 | 12C 表后的「**⚠ 真机安全**」段 | `12.22~12.28 **会驱动机械臂**` |
| 4 | 文末「**回填清单**」 | `把 12.1~12.28 的 \`⏳\` 换 🟢/⚠️/❌` |
| 5 | **`doc/README.md` 的批次索引** | `（TR-101，12.1~12.28：A 档离线 6 条 / B 档 Sim 15 条 / C 档真机 7 条）` |

改完复核：

```bash
python -c "import io,re;t=io.open('doc/test/real_machine_plan_phase3.md',encoding='utf-8').read();ids=re.findall(r'^\| (12\.\d+)',t,re.M);print(len(ids),' '.join(ids))"
# 期望：编号连续无缺、总数 == 索引里写的总数
```

**新用例若也要驱动机械臂，必须把它的危险动作写进「⚠ 真机安全」段**（例：`offsetZ` 取负值时第 1 段是**下降**，
须先目视确认目标点下方不贴桌面 / 不撞夹具 / 无电缆）。

## 陷阱（每条都真实踩过）

1. **Sim 下物理不可判的判据要单列**。`SimCard` / `SimServo` 是**瞬时到位**
   （`MoveAbs … speed=215040`，无真实运动时长）⇒「**减速停**」「续走**从半路**直奔当前段目标」
   「**单调趋近不回摆**」「重复定位精度」在仿真下**无从判定**，必须标注为「需真机复核」，
   **不能**因为「点了按钮、状态变了」就判通过。→ 按**步骤 6** 追加真机用例。
2. **限位导致的「正确拒绝」极易误判成缺陷**。先算物理量再下结论：
   例 `offsetZ` 抬高使 `up z = 基座z + offsetZ` ⇒ `J.z = Pose.z − 165`，
   与 `config.json` 的 `axes.Axis_Z = [−165, 0]` 比对 ⇒ 越界就是**正确拒绝**
   （日志形态：`IK(Smart): no valid solution` + `runner failed: 目标点不可达` + 零运动）。
3. **台账锚点不能用行尾模板**。`TEST_RECORD.md` 每行是**超长单行**，且不同条目的行尾可能同型
   （实测 TR-119 与 TR-120 行尾都是 `（已改回 \`ON\`） |`）⇒ 用行尾做 `str.replace` 会**静默改错行**。
   **锚点必须取该行独有子串**，并加 `assert s.count(old) == 1` 卡住。
4. **用户说「通过」不等于「每条子判据都跑了」**。逐条比对判据里的**每个**构造条件
   （正负值、每个时点、每个状态），缺的如实写成「未跑 / 未命中」，不要顺着「通过」补齐。
5. **清空 / 清表类判据在日志里看不到**。如 `visionResults_` 的清空点，必须**读源码数个数**
   （`RunSequence` / `RunSingleAction` 各一处），日志只能给间接旁证。
6. **改 Markdown 表格后跑 `md-table-check`**；单元格里的 C++ `||` 要转义成 `\|\|`。
7. **严禁把含反引号 / `$` / 括号 / 中文的多行文本塞进 `python -c "…"`**——
   这类文本一律先 Write 成临时文件，再让 python 读文件追加。
8. **用 python 按行号替换整块时，别把块尾的空行一起吃掉**。`lines[iB:iC] = new_block.split("\n")`
   若 `new_block` 不以空行结尾，原 `iC-1` 的**空行**会被一并吞掉 ⇒ 块尾的 `> - …` 列表项与下一行
   **粘连成同一列表项**（CommonMark 的 lazy continuation），整段渲染错乱。
   **替换后必须 `repr()` 看一眼块尾与下一行的边界。**
