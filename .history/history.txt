# 运动控制、回零与 J1 偏移

- BoPai 卡速度单位 Pulse/s，默认速度 = maxSpeed × PulsePerUnit；加速度单位 Pulse/ms²，AccelToPulse = phys × PulsePerUnit / 1e6；rotation 分支 PulsePerUnit 必须除 gearRatio。
- inverted(direction=1) 统一逻辑坐标：下发取反、回读也取反；软限位、界面、按钮方向全部用逻辑坐标。
- 回零：HomeAxis 只下发不置 homed；卡轴在 PollCardAxis 观测 running 结束且过 1s 保护期后 MarkAxisHomed；舵机用原始机械角 |angle|≤1° 判定（不能用逻辑角，J2 offset=28 会永不满足）。homingActive_ 是过程门禁，AbortHoming 只复位回零中的轴。
- 回零参数：homeDir/homeSns/homeRapidVel/homeLocatVel/homeBackDis/homeMaxDis；homeMaxDis 必须非零；MC_HomeSns 是全局位掩码；HomeAxis 持锁时禁止调 GetAxisStatus；StopAxis 先 MC_HomeStop 再 MC_Stop。
- 软限位拦截必须看运动方向：仅拦截仍朝越界方向运动者，朝界内放行；静止在边界不触发；PollTick 回零中的轴不拦截。
- Home Offset：逻辑角 = 机械角 − homeOffset；J1 offset=102°、J2 offset=28°，其余 0；J1 限位 [-102,8]、J2 [-28,152]。
- XRServo 使用 FashionStar 协议（0x4C12/0x1C05），J2→id0、R→id1；共享串口句柄 + 串口级互斥；点动走 cmd8 并按增量算周期；停止用 cmd24 mode=1；TorqueOn 也用 cmd24 锁位；MoveToAngle 前先 QueryAngle；角度统一 wrap 到 [-180,180]。
- 180° 三坑已修：QueryMonitor wrap、TorqueOn 不用 SET_ANGLE 锁位、MoveAtSpeed/MoveToAngle 前 ±360 对齐；R 域 [0,185] 仅软件校验域。
- 舵机连接语义（TR-070）：IsServoConnected 收紧为串口打开且所有已创建舵机 IsOnline；Initialize/ReconnectServos 中 SetServoId/SetSpeed 必须在 Connect 之前；上电恢复走 Ping ok skip reconnect + PollTick 边沿广播。已知开口：skip-reconnect 路径不重写 addr=44 accel 参数。
- J1 开环失步：卡内 lAxisPrfPos 是指令计数器而非反馈，UI 数值不变不能证明软件无罪；下一轮同一绝对目标发 0 脉冲，物理短少永不纠正。收口值 maxAccel 200→80 °/s²、maxSpeed 30→25 °/s（提交 4c95d14）；09-18 连续 247 轮约 4h 无可见漂移。有效杠杆是加速度（斜坡段失步），降加速度拿节拍换精度，与 P6 节拍优化冲突。
- TR-090 停止滑行：接线 MC_SetStopDec；真机标定 J1 与 Z 的 stopDecSmooth=1.0，其余轴暂不动。开环步进所有停止必须走 MC_Stop 减速斜坡，禁止瞬间断脉冲；点动停止本来就是减速停（TR-085 零代码改动）。
- 夹爪：轴5 绝对目标坐标，0=夹紧、负=松开，软限位 [-5,0]mm；动作 gripperTarget 越界拒绝、不静默改写；速度 = GetMaxSpeed(Gripper)×speedPercent；到位超时按 GetAxisBusyMs 动态兜底。旧版 isGripperOpen 与物理方向相反已废弃。

# 执行引擎、动作树与循环生产

- SequenceWorker 显式状态机 WorkerState{Idle,Running,Paused,Fault} + PauseReason{None,User,Step}；stateChanged 为 enum 签名；IsRunning()=state!=Idle（单步暂停亦 true）。
- 三级停止：Stop() 仅置 cancel，执行完当前动作才停；StopImmediate() = cancel + StopAllAxes 减速停保持使能（自动页停止）；EmergencyStop() = cancel + 断使能（顶栏急停）。Pause 点级暂停：减速停当前轴、挂起保持上下文；Resume 重发当前绝对目标原地续走；Delay 按剩余时间续算，回抽阶段暂停不反向补料。
- 自动运行页 5 按钮：▶启动/继续、⏸暂停、■停止、↺清报警、⟳初始化；原「复位」实为 HomeAll 已归手动页。初始化只建连接 + 读轴配置 + 启 50ms 轮询 + 状态归零，不含使能/回零。
- 单步：SetStepMode(true) + RunSequence，每动作后 Paused(Step) + WaitForStep；WaitForStep 在循环体内，最后动作也挂起，故 N 个动作需 N+1 次点击。stepMode 清除点在会话结束（StartExecution 末尾 / RunSafePos 双保险），不能在 RunSequence 入口清。
- 单步回归教训：stepMode 清除点错放 RunSequence 入口导致一次跑完（TR-076）；执行选中动作先清会话标志后被拒导致死锁（TR-077）。会话标志清理必须放在操作成功确认之后或会话结束。
- 单步按钮执行期同步禁用（点击栈内 setEnabled(false)），防 queued 信号竞态导致连跑两个动作；切换/删除方案执行期门禁 IsExecutionActive()。
- P6 动作树：ActionData 加 nodeType(action/group) 与 children，SchemeData.actions → nodes；读取兼容旧键 actions，nodeType 缺省 action，非法嵌套加载时扁平化。Group 不进 ActionType 枚举。
- 分组并发：不采用 QtConcurrent 多线程，改单线程协作式 RunScheduler（20ms tick，同时下发、统一汇合）；并发省的是等待时间而非计算时间。组内失败先安全停全部子动作再返回，失败归因首个失败者；retryCount 对分组取整组重试；分组整体算单步的一步。
- 分组不允许嵌套；OnNewGroup 把插入位置硬编码在一级 ⇒ 结构上只能一级；validateGroupChildren 的嵌套拦截是保存路径兜底。校验按资源不按类型：Move 与 VisionGuide 共用四轴，Delay 空集；依次做嵌套、数据依赖、资源两两求交。
- 动作编号：ActionData.id 方案内唯一正整数，SchemeData.nextActionId 单调递增不回退；插入/删除/移动不重排、不回收；加载时缺失/非正/重复按方案内最大+1补发，幂等、惰性升级（不回写磁盘）。normalizeActionIds 在改动数>0 时由调用方打 normalized N of M node(s) 日志；分组嵌套拉平计数按被改写节点数记 1（TR-121）。
- 循环生产 TR-091：LoopConfig 模式 Single/Count/Infinite + count + returnToSafePos + retryCount/retryDelayMs；cycleChanged 每轮发一次，schemeFinished 只在全部循环完成时发一次；循环间隔内联回安全位；Single 的 total 必须为 1（曾与 Infinite 共用 -1 被渲染成 1/∞，TR-119）。
- errorOccurred 单点化：ExecuteAction 子树 8 处 emit 改为写 Impl::lastError，emit 收敛到 ExecuteOnce 失败分支与 StartSingleExecution 兜底 2 处；内部中止用 aborting 与用户 cancel 分流，避免把动作失败误报成用户停止。
- 严格先抬 Z：DispatchPointMove 对目标与读回差 ≤0.01 的轴跳过下发并打 skip axis X (in position)，跳过前仍过软限位。到位判定本质是时间估算（dist/spd+200ms，非反馈），点1 重下发 J1/J2/R 读回值可能引入微差，故需 ε 跳过。
- 视觉引导 TR-101：sourceActionId 指定识别动作编号（不跨方案、不依赖时序邻近）；offsetZ 按末端高度 Pose.z 算、正值向上，与 PointData.j3 严格区分；guideR 默认 179.9（不用 180 贴回绕奇点）；两段移动复用 PrepareRunnerSegment → ResolveRunnerJoints → DispatchRunnerSegment；零 TCP 变换；PuffResult.yaw 是相机平面 yaw，与 R 无关，忽略并日志留证；识别坐标只进日志和会话内存，不写 process.json。

# 安全位、急停与 UI 互锁

- safePos 为关节角形态，config kinematics.safePos.{j1,j2,z,r,enabled}；enabled 默认 false，示教后置 true；实为总开关，同时控制自动（回零上升沿）与手动（回安全位按钮），UI 文案「启用安全位」。
- 自动回安全位只在「未回零→已回零」上升沿触发，即软件启动后第一次一键回零；已回零重回零、单轴重回零、单步暂停中重回零均不触发。
- 急停恢复链（TR-081）：急停 → 切手动 → 使能 → 一键回零 → 手动回安全位 → 切自动 → 启动。急停不清已回零轴 homed，恢复回零无上升沿，故不会自动回安全位；方案 B（急停清全轴 homed 造上升沿）因影响面大被否决。
- estopPending_ 在 HardwareManager（硬件级全局状态），页面禁止自持副本；EmergencyStop 置位须在 emit enableStateChanged 之前；唯一清除条件 = 急停后全轴回零，先清后发 estopCleared。
- 模式互锁：自动模式导航白名单 {自动运行, 视觉检测}；VisionTestPage::SetParamsLocked 锁参数控件；Running/Paused 禁止切模式并 QSignalBlocker 回弹，Fault 放行；切回自动时强制 ProcessPage::AbortStepSession 清单步会话。
- ApplyModeState 是模式态唯一出口；标签高亮必须放在 ApplyModeState，不能留在 toggled lambda（回弹被屏蔽会残留被拒模式色）；强制跳页双写 setChecked + setCurrentIndex。
- 全局消息横幅 TR-092：AutoRunPage::SetHint → requestGlobalHint → MainWindow::UpdateGlobalHint → HintBanner；HintBanner 必须是 MainWindow 成员，固定宽 320，超长 ElideRight，点击弹非模态 QMessageBox（不能 exec 阻塞），elide 在 SetMessage 与 resizeEvent 双点重算，用 QLabel 派生而非 QPushButton。
- 手动页提示保留原地；急停/回零提示与舵机重连提示竞争时，急停锁存期间抑制重连提示（TR-087）；回零完成绿字③锁存，安全位会话完成态特判（TR-088）。

# 深度法算法与手眼标定

- 算法配置：AlgorithmParams/PuffResult 扩展，vision.algorithms.<算法名> 为算法私有参数命名空间，HardwareManager 透传整棵子树；覆盖关系 = 算法节点优先、通用域作默认。PuffResult.x/y 保留但算法侧不填（恒 0），视觉页两列由 PixelToRobot 实时算。
- 算法接口契约（冻结）：算法只吃一帧图像 + 参数快照，只出像素 + 深度 + 尺寸 + 置信度；不碰内参/手眼/坐标转换/ConfigManager。输入彩色 RGB888 + 深度 float mm（depthWidth/Height，0=同彩色，≤0 无效）；输出 PuffResult 含 area/minDepthMm，z 语义为区域最高点，results.front()=最佳目标（隐性契约）。跨进程形态 = 图像 .bin + JSON 只带路径/尺寸/格式/参数；升级路径 = ExternalPuffAlgo 适配器。未决：传输方式（stdin/stdout、常驻进程+socket、文件轮询）与 protocolVersion 兼容规则。
- 深度法移植来源：老项目 robot-puff/Framework/VisionModule 的 CPuffLocator（PuffLocator.h 86 行 + cpp 407 行，核心 6 函数零 MFC）；落地 src/HAL/algorithm/DepthPuffAlgo.{h,cpp}，注册名 DepthPuffAlgo；仿真下只检出 1 个目标（颜色法 2 个）属预期行为变化。
- 移植关键坑：HAL 原不链接 OpenCV，须加 ${OpenCV_LIBS}（运行时 DLL 已由构建/打包带走）；算法在深度域做连通域，契约要求 pixelU/pixelV 在彩色系，输出前须按比例归一（D2C=SW 时退化为恒等）；老实现只返回 argmax 一个，改 vector 后必须显式按 score 降序排序（SequenceWorker.cpp:1034 直接取 front()）；z 取最高点 minDepthMm，老实现区域均值仅留日志；PuffLocator.h 成员默认值与 puff_locator_params.json 不一致，以 JSON 为准；两套 confidence 语义不同，通用域 0.85 对深度法过严但必须消费该键；m_dDepthScaleToMm 不移植。
- 深度法真机调参（TR-131~135）：节点级 confidenceThreshold=0.65（真球 score ≥0.697、垃圾 ≤0.611；通用域 0.85 不动）；排序键改 minDepthMm 升序（后改 apexDepthMm），results.front()=最高泡芙；PuffResult 增加 bboxX/bboxY，pixelU/V 改球顶（深度最小 apexPercentile 面片质心），z 取该面片均值深度（抑制 flying pixel，帧间抖动 ±3mm→±1mm）；apexPercentile 默认 0.02，clamp [0.005,0.5]，面片≥8px；多目标合并用距离变换 FindMarkers + VoronoiSplit，尺度自适应 NMS（minSep=1.0×dist.max()、minPeak=0.55×dist.max()），单球几何上不可能切出 2 个峰；heightBandMm=20 不可调大（25 起盒面冒垃圾，30 两球并成一个连通域，40+ 整盒淹没）。
- 手眼标定（2026-10-15 评审）：doc/hand_eye_calibration_plan.md §4.2 方法 B（点对反推）；精度门槛 1px≈0.48mm（fx=1037.46、z_c=500mm），XY≤1.0mm ⇒ 质心容差约 2px、深度容差 2mm；同一高度常量像素偏置会被 t 吸收，真正门槛是「一致 + 对应」而非绝对准。标定针对可见性零帮助；标定板是唯一同时解决「不用看尖端」+「顺带解出 R」的路线（vcpkg OpenCV 已有 cv::calibrateHandEye/ArucoDetector），但建议先走用户方法、残差证伪倾角后再上板。
- 用户提出方法 B′：夹爪尖端触碰固定点→做记号→挪开臂→相机识别记号取 u/v/depth，多高度多位置采 9 点→逐点解 Ox/Oy/Oz；可行且优于 §4.2 方法 B（靶点=真值点、无遮挡、易重复、多高度可验倾角）。四处必须钉死：记号中心=触点；记号面=触点面且要真多高度；按算法选靶并先修配置（depthZMin/Max 现 6/496 而真机有效深度 164~2260mm、confidenceThreshold 0.85 对深度法过严、一次只放一个靶、臂须移出视野、Vision calib 行只在「识别」动作里打）；标定点受可达环 81.03~358.69mm 约束。已提议作为「方法 B′」补进 §4.2，尚未裁定、未动文档/代码。

# 行业认知与技术路线

- ROS2 与现实现本质差异：指令式（上位机发目标位置+速度，卡端自治梯形规划，50ms 轮询判到位）vs 周期同步式（controller_manager 每周期 read→update→write，joint_trajectory_controller 1kHz 插值）。IMotionCard 层不会消失，映射为 hardware_interface::SystemInterface；被替换的是编排/规划/控制三层。
- 博派卡 MC_PrfTrap 是「设参数-启动-跑完」指令式，不是周期位置跟随；上 ROS2 前须查手册确认是否有 PVT/连续位置模式，否则只能「卡继续插补 + ROS2 只做上层编排」。
- 卡当前承担六项职责：脉冲发生、梯形规划、回零状态机、停止曲线、状态聚合、点动（BoPaiCard.cpp 均有 MC_* 调用点）。去卡需硬件：Linux+PREEMPT_RT、EtherCAT 主站（IgH/SOEM 或 ros2_canopen）、4 台 CiA402 总线伺服/闭环步进、编码器（J1 建议绝对值）、原点/硬限位、安全继电器+STO、可选远程 IO；软件：ros2_control + 自写 SystemInterface + broadcaster/controller + 自写回零/夹爪/挤出 controller + MoveIt2 + Orbbec ROS2 驱动 + easy_handeye2 + BehaviorTree.CPP/MTC + RViz2/rosbag2/PlotJuggler。
- 核实：卡数字 IO（SetDO/GetDI）业务代码零调用；transmission.encoderResolution 是电机每转脉冲数而非编码器配置（J1 25600/360/0.01=7111.1 Pulse/°），系统无编码器反馈、纯开环。去卡最大成本是电气改造；实时性责任从卡端移到 Linux 实时内核，对节拍是净增加。若只为解决 J1 失步，换闭环步进驱动器（保留卡发脉冲）成本低一到两个数量级；若为 ROS2 生态则无需去卡。
- ROS2 换不掉 SequenceWorker 的暂停/停止/单步/循环语义（仍须自写，只换宿主）与 J1 开环失步（根因在开环脉冲丢失）；能换来手眼标定工具链、RViz2/rosbag2、MoveIt2 碰撞检测、URDF 换型。
- 行业形态：传统工业机器人驱动器集中柜内（柜大）；小型 SCARA 驱动器内置控制器盒；协作机器人驱动器进一体化关节（控制箱极小）；PC-Based 通用（驱动器柜内+脉冲接线，本仓库属此类）。柜体体积主要由驱动器+电源+端子排+安全回路决定，运动控制器只占一小块；驱动器位置下沉（柜内→控制器盒内→关节内）才是柜体缩小的真正原因。
- 「上位机集成+一个盒子」= PC-Based 软件控制主站形态（Beckhoff TwinCAT、CODESYS SoftMotion、SCATECH SCmotion 4.0）；省掉的是控制器而非驱动器，驱动器不进电机/关节则柜体不会显著变小。本机是视觉引导抓取+挤出+循环生产的非标设备，PC-Based 是合理选择，柜体大是该路线固有代价；缩柜路径按代价排序：换总线驱动器→换一体式伺服→加软件主站省卡→一体化关节。本仓库已是软件主站雏形，缺实时内核与总线驱动器。
