# Z 轴标定结果与五步验证法

- 以下为 Gemini 给出的 Z 轴验证方案，五个步骤均已真机验证通过（2026-08-26）。
- 步骤 1 底层参数验证（防炸机）：在【电控与映射】填入 Pulse/Rev=25600；确认 Z 轴丝杠导程（常见 5/10/20mm）填入 Lead；手动用金属片遮挡 Z 轴限位开关，经控制卡诊断工具或底层日志确认 HOME 信号有效、极性（常开/常闭）配置正确。
- 步骤 2 方向与单轴回零：点 JOG+ 必须向上升、JOG- 向下降（反了改配置 Inverted）；点【回零】后期望电机向上寻找限位，碰金属片后停止并清零为 0.0mm。
- 步骤 3 精度实测：目标框输入 -100 点 Go，用钢卷尺实测滑台下降须恰为 100mm；若只有 50 或 200mm，说明配置中 Lead（导程）或 GearRatio（减速比）填错。
- 步骤 4 软限位探底：以极慢速（如 5mm/s）一直按住 JOG- 下行，至夹爪尖端即将碰到桌面/机械死角时松开，记录当前位置（示例 -280.0mm）；去【电控与映射】设 Limit Min=-280、Limit Max=2（留余量）；再次回零后输入 -500 点 Go，系统应瞬间拦截提示超出软限位，绝不能让电机真跑下去撞碎夹爪。
- 步骤 5 终极 3D 坐标系验收：配置 Z_0=470、h1=175、tcpDown=130；验证 1（高空）—Z 回零后右上角坐标系 Z 必须显示 165.0mm；验证 2（桌面）—Go 输入 -165 让电机下行，夹爪尖端刚好亲吻桌面，且 Z 显示 0.0mm。
- 标定结论：Z0=470、h1=175、tcpDown=130 为现行基准值，Z 轴标定完成（对应计划 3.4）。

# 舵机掉线与重连行为

- 现象链（2026-08-25/26 真机日志实证）：ReadTelemetry 失败（「响应超时」或「串口发送失败」，XRServo.cpp:499）→ HardwareManager 判定离线（08-25 版约 1s 阈值、08-26 版约 2s 且带 Ping 门卫）触发重连 → 两舵机一起 Disconnect/Connect（COM3 @115200，WriteUserData addr=44，重设 id 0=J2 / id 1=R）→ 重连成功（日志见 Servo id online 及角度）→ 但使能标志已复位，手动页状态灯变灰，此时点动/Go 被 MoveAbs rejected: axis not enabled 拒绝 → 重新点「全局使能」（SendSetAngle 锁当前角 interval=1000ms）后完全恢复正常运动。
- 失败有两种形态：偶发单帧超时后自行恢复（不需重连）；成片连续失败（约 300ms 一轮、双舵机同时报「串口发送失败」）必然触发重连。两次重连均一次成功。
- 行为语义已获用户认可：掉线→状态灯灰属正确逻辑；重连后必须重新使能才能运动是使能门禁的正确行为；不做掉线后自动使能（违背使能门禁设计）。
- 用户硬性要求（业务约束）：要么不能掉线，要么掉线重连之后不能影响前台操作以及后面的自动化运行。
- 掉线根因未定：设备运行中硬件接口并无插拔断开，属软件判定掉线，会影响设备运转感；此前分析倾向 USB 转串口硬件层（EMI/线缆接触/供电/COM 口被占用），软件侧已有滑动字节对齐、失败重试等加固但仍复现，需现场继续排查。
- 复盘材料：log/creampuff_YYYY-MM-DD.log（如 creampuff_2026-08-26.log）。

# Kinematics 重构原则

- 原则 1 等效小臂模型与强语义 TCP：物理模型严密验证后彻底重写 Kinematics.h/.cpp，夹爪直接安装在 J4 前方并朝下。保留外部配置接口 SetTCP(offsetX, offsetY, offsetZ) 与 config.json 联动；类内部删除 dx_/dy_/dz_，改用 tcpForward_=0.0（沿小臂 L2 向前）、tcpDown_=0.0（竖直向下物理距离，绝对正数）。
- SetTCP 映射：tcpForward_=offsetX；tcpDown_=-offsetZ（传入 offsetZ 为负表示向下）；offsetY != 0 时 SPDLOG_WARN「当前模型忽略 Y 向 TCP 偏移」。正逆解中小臂有效长度 l2_eff = l2_ + tcpForward_。
- 原则 2 甜甜圈工作空间校验：l2_eff 可能大于 l1_，工作空间为中空圆环。ikSolve 双向边界检查：r > (l1_+l2_eff)+0.001 或 r < fabs(l1_-l2_eff)-0.001 时目标不可达，打印警告返回 false；彻底删除原原点奇点处理（原点物理上不可达）。
- 原则 3 Z 轴高度推导：Z0 为撞顶时大臂上表面绝对高度，h1 为大臂向下倾斜固定垂直落差，tcpDown_ 为夹爪向下延伸长度；SetParams(l1xy, l2, z0, h1)。正解：夹爪尖端真实高度 = 电机物理高度 + z0_ - h1_ - tcpDown_；逆解：电机物理高度 = 目标尖端高度 - z0_ + h1_ + tcpDown_（早期无 tcpDown_ 项的表述作废）。
- ConfigPage.cpp【运动学参数】Tab 在 L1、L2、Z0 旁追加 h1（大臂落差）输入框，与 config.json 的 kinematics.links.h1 双向绑定。
- 重构一律以 config.json 实际值及新测值为准（早期 prompt 示例 l1=174.35/l2=215 作废）。

# HomeOffset 逻辑零点机制

- 语义：逻辑角度 = 机械角度 - homeOffset（机械零点=回零位置，逻辑零点=工艺示教零点）。J1 offset=102°、J2 offset=28°、其余轴 0。所有界面/软限位/运动学统一使用逻辑坐标。
- 软限位随 HomeOffset 同步偏移（用户明确要求）：J1 物理 0~110° → 逻辑 limitMin:-102.0/limitMax:8.0；J2 物理 0~180° → 逻辑 limitMin:-28/limitMax:152。config.json 默认值已同步更新。
- 回零后逻辑位置为 -offset；所有逻辑坐标经硬件层单点转换（MoveAbs 下发 机械=inv?-(逻辑+off):(逻辑+off)、GetPosition 回读减 offset），不得在别处再加减偏移。实现全部落在 HardwareManager 门面层，AxisConverter 保持纯机械坐标↔脉冲不感知偏移。
- 已自测验证（驱动测试 24/24 通过，2026-08-19）：回零→逻辑 -102/-28、Go 逻辑 5→机械 -107（inverted）、点动撞界自动停、越界拒绝/反向放行。
- 期间修复两个隐藏 bug：SimCard::SetAxisConfig rotation 分支漏 gearRatio（ppu 错 100 倍 → 点动撞界夹紧失效）；MoveJog 启动边界检查容差太紧（浮点舍入 7.99996875），改 0.01。

# 夹爪机构与软限位

- 夹爪电机轴是一根短丝杆，丝杆上有螺纹环，螺纹环带动夹爪松开/夹紧。螺纹环靠近电机 → 夹紧；远离电机 → 松开。从电机轴向看：顺时针=松开、逆时针=夹紧。
- 回零动作默认是夹紧：螺纹环上的限位金属片接触电机轴根部限位开关触发回零。
- 夹爪软限位 -5~0mm 来源：回零后位置显示 0；松开后位置显示负值 → limitMin=-5、limitMax=0。
- 软限位反向拦截 bug（已修复并真机验证）：惯性越界到 0.2 后持续按「松开」无反应、越界后 Go 到界内也无反应。根因是软限位拦截未区分运动方向（与 J1 曾遇问题同源）——惯性越界后朝边界内运动的请求也被拦截。修复为按运动方向判断，仅拦截仍朝越界方向运动的动作，朝边界内运动放行。
