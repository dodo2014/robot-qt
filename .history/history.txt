# J1 关节累积偏移（TR-095，2026-09-15 发现 → 2026-09-18 真机收口 🟢）

- 现象：循环生产约 15 轮后回到方案 1 初始位置，关节 2 / 夹爪向 Y+ 偏移、J1 目测逆时针偏移、Z 无偏移。
- 定位：**软件侧用真机日志实测排除**（J1 当日下发 1333 次、不同目标值仅 4 个、零变化）。根因机制 = **卡内 `lAxisPrfPos` 是指令计数器而非反馈**——开环步进失步对它不可见（故「UI 数值不变 ⇒ 软件无罪」推理**无效**），且下一轮下发同一绝对目标时卡发出 **0 个脉冲**，物理短少永不被纠正；**绝对定位不是安全保证，而是误差只累积不回落的前提**。
- 收口值（提交 `4c95d14`，2026-09-16）：`maxAccel` **200 → 80 °/s²**、`maxSpeed` **30 → 25 °/s**。逐日日志对照：09-15 下发 200 °/s²（370 次）且观察到漂移；09-18 下发 80 °/s²（1333 次，唯一档位）连续 **247 轮（≈4 h）无可见漂移**。
- 机理细化：**有效杠杆是加速度而非速度**——巡航段力矩需求仅摩擦与重力，斜坡段 = 转动惯量 × 角加速度 ⇒ 失步主要发生在斜坡段。**降加速度是拿节拍换精度，与 P6 节拍优化直接冲突**。
- 遗留：判定仍为**目测级**（残余失步是否归零未知，长循环前须做定量读数）；`maxAccel` 上限边界未扫描。
- 教训（已沉淀）：写问题分析文档前**必须先 `grep TEST_RECORD.md`** 查是否已有 TR——本次 TR-095 早已专记该问题且证据链更细，助手把「软件指令恒定」误当新发现。

# 技术路线与行业认知（2026-09-22，纯咨询未落盘）

- **ROS2 路线（三轮咨询）**：本质差异 = **指令式**（上位机只发目标位置 + 速度，卡端自治跑梯形规划，上位机 50 ms 轮询判到位）vs **周期同步式**（`controller_manager` 每周期 read→update→write，`joint_trajectory_controller` 1 kHz 时间插值）。`IMotionCard` 层不会消失（映射为 `hardware_interface::SystemInterface`），被替换的是其上三层。**关键前置可行性问题**：博派卡 `MC_PrfTrap` 是「设参数-启动-跑完」的指令式模式，须先查手册确认是否有 PVT / 连续位置模式，否则 ROS2 控制层无法落地。
- ROS2 **换不掉**的：`SequenceWorker` 的暂停 / 停止 / 单步 / 循环生产语义（`ros2_control` 不提供，仍须自写）、J1 开环步进失步（根因在开环脉冲丢失，与规划框架无关）。ROS2 **能换来**的：手眼标定工具链（`easy_handeye2`，当前矩阵为**占位值**，是真机验收阻塞项）、RViz2 + rosbag2、MoveIt2 碰撞检测（替掉自研甜甜圈校验）。**风险**：实时性责任从卡端硬件移到上位机（需 PREEMPT_RT，Windows 难达标），对节拍是净增加。
- 去卡所需组件（硬件：Linux + PREEMPT_RT、EtherCAT 主站、4 台 CiA402 总线伺服、编码器、原点 / 硬限位、安全继电器 + STO；软件：`ros2_control` + 自写 SystemInterface + controller + MoveIt2 + Orbbec ROS2 驱动 + `easy_handeye2`）。**核实**：卡的数字 IO（`SetDO`/`GetDI`）在业务代码中**零调用**；`transmission.encoderResolution` 是「电机每转脉冲数」**而非编码器配置**（J1 换算 25600 / 360 / 0.01 = 7111.1 Pulse/°，与代码一致），**系统无编码器反馈通路、纯开环**。判断：若目标只是解决 J1 失步（TR-095），**换闭环步进驱动器（保留卡发脉冲）成本低一到两个数量级**。
- 行业认知（用户主动提出）：机器人柜体体积主要由**驱动器 + 电源 + 端子排 + 安全回路**决定，运动控制器只占一小块；主线判断 = **驱动器位置下沉**（柜内 → 控制器盒内 → 关节内）才是柜体缩小的真正原因。本机属 **PC-Based 通用**形态（驱动器柜内 + 脉冲接线），柜体大是该路线固有代价。

# 自动运行页 5 按钮与底层状态机重构（TR-073，2026-09-07 已落地）

- 来源：用户与 Gemini 的深度业务架构讨论（工业标准语义纠正）+【架构指令 1/2】。核心纠偏：
  - **【停止】≠【复位】**：停止 = 废弃当前流程上下文、回就绪态，再启动从第一步重跑；**"从中断处继续"是【暂停/继续】**，不是停止+复位；【复位】= 清除报警（Clear Alarms），绝不含让机器动起来的逻辑。
  - **开环步进禁止瞬间断脉冲**：惯性导致丢步、坐标系永久错乱（伺服有编码器闭环才能"立即停"）。所有停止必须走 **MC_Stop 减速斜坡**（BoPaiCard.cpp:327），视觉上快停但微观是降速斜坡；若减速距离不可接受，调 `MC_SetStopDec`，不改停止方式。
  - **初始化两层**：软件层 = `HardwareManager::Initialize()`（连卡/相机/查状态）；物理层 = 回零 + 到安全位。同事经验的"原点/初始位/安全位"三者中，**全局安全位必须单独配置**（急停后机械臂在低位，直接启动方案会横扫桌面设备）。
- **5 按钮**（下标分派，不再靠 text.contains 匹配）：`▶ 启动/继续`、`⏸ 暂停`（Pause，减速停+保持上下文，Resume 原地续走——重发当前绝对目标 MoveAbs，不重跑整个动作）、`■ 停止`（**StopImmediate** = cancel + StopAllAxes 减速停，保持使能）、`↺ 清报警`（ClearFault，仅清引擎锁存，不自动使能）、`⟳ 初始化`（仅 Initialize + 分级引导，不含使能/回零）。原「复位」实为 HomeAll，已归手动控制页。
- **状态机**：`enum class WorkerState { Idle, Running, Paused, Fault }` + `PauseReason { None, User, Step }`（Q_ENUM，跨线程 Queued 必需）；`stateChanged` 改 enum 签名（原 QString 中文字符串已废）；`IsRunning() = state != Idle`（单步暂停亦 true，语义零回归）。点级暂停 + 原地续走（PauseGate）；Fault 锁存由 ClearFault 清除；`Stop()` 保持"仅置 cancel 就近"语义供单步/退出用。
- **顺序决策（Gemini 定）**：必须先做按钮语义重构（1/2），再做权限互锁（2/2）——互锁是"建在状态机上的外墙"，先建墙会全部推倒重来。

# TR-084 退出悬垂崩溃根治与 QPointer 观察者指针规约（2026-09-09/10）

- TR-084 关闭软件时崩溃（`0xc0000005`，由 `log/crash.txt` 捕获，阶段 9 期间发现并修复）：存在未完成会话（Running/Paused/挂起）时关软件即崩；崩溃栈 = `~MainWindow` → `ShutdownWorker:229`(processEvents) → `AutoRunPage::OnInterrupted:532` → `UpdateControlsEnabled:563` → `m_worker->GetState()` 访问违规。
- **根因（结构性，非「漏判空」）**：`SequenceWorker` 由 `MainWindow.cpp:159` 的 `connect(workerThread_, &QThread::finished, …, deleteLater)` 交事件循环销毁，而 4 个观察者（MainWindow/AutoRunPage/ManualControlPage/ProcessPage）持**裸指针**——判空只能判 null、判不出悬垂。退出时序：ShutdownWorker 调 `Stop()`（有会话时产生 `interrupted`）→ `quit()` → 线程收尾执行 deleteLater → 主线程 `processEvents` 派发**已排队**的 `interrupted`（Qt **不会**因 sender 析构回撤已 post 的 QMetaCallEvent）→ 槽访问已释放内存。叠加隐患：`sequenceWorker_` 声明在页面**之后**（MainWindow.h:54-56 vs :60），成员逆序析构时 worker 早于页面。
- **决策（用户选方案 C）**：观察者指针改 `QPointer`（对象析构自动置空），**不动退出时序**——`ShutdownWorker:229` 的 processEvents 是防 `BlockingQueuedConnection`(`InMainThread`) 挂死的**刻意设计**，改错会变成「退出挂死」（比崩溃更难查）；方案 D（去 deleteLater / 重排析构）据此否决。
- **实施（`d1d5346`）**：4 处声明 `SequenceWorker*` → `QPointer<SequenceWorker>` + 4 个头 `#include <QPointer>`（ManualControlPage.h 另需完整定义——其内联 setter 赋值需要完整类型）+ 补 `MainWindow.cpp:166` lambda 判空（唯一无判空访问点）。**关键便利**：Qt 6.11.1 的 QPointer 保留隐式 `operator T*()`（`qpointer.h:83`）→ 22 处 connect 的 sender/receiver 与全部 `->`/传参/三目/赋值**原样可用，0 处需 `.data()`**；成员声明只需前向声明、无需改 include 为完整定义。已核实无裸指针临时副本、无容器存储、无 invokeMethod（`ProcessPage.cpp:875/922` lambda 虽无判空但 sender 即 m_worker，析构自动断连，安全）。
- **状态**：🟡 已修复待真机验证（Debug+Release 双编译 EXITCODE=0 + Sim 冒烟 SMOKE_INIT_COMPLETE=True；退出复现需真机）。`log/crash.txt` 定位后已清空，崩溃栈记录保留于 TEST_RECORD TR-084。
- **规则沉淀（`doc/architecture.md` §5 关键不变量）**：跨线程 / 长生命周期 QObject 的观察者指针**一律用 QPointer，禁止裸指针长期持有**。
- **两条通用教训**：① **判空只防 null、不防悬垂**——对象若由 `deleteLater` 或父对象销毁，观察者必须用 QPointer；② **已 post 的跨线程 Queued 信号在 sender 析构后仍会派发**，不要假设断连/析构能回撤。**安全论证要基于事实**：回零是**重建**坐标基准（非「使其失效」），残留会话的真正危害是**位姿不连续**（从机械原点直冲旧方案下一**绝对**目标，而四轴独立 MoveAbs 无「先抬 Z」前提）+ 异步竞争致 Fault 锁存。

# 关键术语：上升沿/电平语义 与 WorkerState 四态

- **电平 vs 上升沿**：电平 = "当前是什么状态"；上升沿 = "从 false 跳到 true 的那一瞬间"（类比 PLC 的 `|P|`）。`homeStateChanged(bool homed)` 是**电平语义**——只要"全轴 homed"成立就 emit true，**单轴重回零（其余轴 homed 保持）会重复 emit true**。故 MainWindow 用 `lastHomed_` 造上升沿（`rising = homed && !lastHomed_`，且无论是否 rising 都要更新 lastHomed_ 为下次留基准）；否则操作员单独回零 J1 时会误触发安全位走位（危险）。
- **同源陷阱**：`IsSystemHomed()` 不可用于判定"急停是否恢复"——`AbortHoming` 只复位"正在回零中"的轴，已回零完成的轴 homed 保持 true（TR-062）→ 急停后 IsSystemHomed() 很可能仍 true。故急停用独立 `estopPending_` 锁存。一句话：该信号告诉你"现在是什么状态"，不告诉你"刚刚发生了什么事件"。
- **WorkerState 四态**：Idle = 没有会话在执行（引擎空闲，注意 ≠ 已使能/≠ 已回零/≠ 无故障/≠ 轴静止）；Running = 正在执行动作；Paused = 挂起保留上下文；Fault = 上次失败且未清除（软件锁存）。离开 Idle 只有三条路：RunSequence / RunSingleAction / **RunSafePos**（安全位期间亦非 Idle）。
- **确认处于 Idle 的判据**：① 日志最近一条 `state -> 0 reason 0`；② 自动页五钮矩阵；③ ⚠ **不可用状态标签判断**——`UpdateStatusByState` 的 Idle 分支故意不覆盖标签（AutoRunPage.cpp:622-624）以保留「✅ 完成」「⏸ 中断」终态。

# 舵机重连抖动治理与硬件定性

- 「半死」设备时指数退避失效（重连成功归零→1-2s 又断→立即再连）；离线遥测占满 UI 线程致急停/使能秒级无响应。软件修复五项：成功冷却 30s、离线遥测降频 1s、已离线单次尝试、Ping ok skip 退避 2s→15s、删噪声日志。

- 运维规程：不要 24h 连续通电、不用时断使能降温、失联先断电重启舵机。

# Kinematics 重构原则

- 原则 1 等效小臂与强语义 TCP：保留 SetTCP(offsetX, offsetY, offsetZ)；内部 tcpForward_=offsetX、tcpDown_=-offsetZ（offsetY!=0 时 WARN 忽略）；l2_eff = l2_ + tcpForward_。
- 原则 2 甜甜圈工作空间校验：r > (l1_+l2_eff)+0.001 或 r < |l1_-l2_eff|-0.001 时不可达返回 false；原点物理不可达，删除原点奇点处理。
- 原则 3 Z 轴高度：正解高度 = 电机物理高度 + z0_ - h1_ - tcpDown_；逆解电机物理高度 = 目标尖端高度 - z0_ + h1_ + tcpDown_。ConfigPage 运动学 Tab 有 h1 输入框双向绑定 kinematics.links.h1。

# HomeOffset 逻辑零点机制

- 逻辑角度 = 机械角度 - homeOffset。J1 offset=102°、J2 offset=28°、其余 0。界面/软限位/运动学统一逻辑坐标。
- 软限位同步偏移：J1 limitMin:-102/limitMax:8；J2 limitMin:-28/limitMax:152。
- 单一转换点在 HardwareManager 门面层；AxisConverter 纯机械↔脉冲不感知偏移，不得在别处再加减。

# 夹爪机构与业务边界

- 夹爪电机轴是短丝杆，螺纹环靠近电机=夹紧、远离=松开；从电机轴向看顺时针=松开。回零默认夹紧（限位金属片碰电机轴根部开关）。
- 软限位 [-5,0]mm：回零后显示 0、松开显示负值。
- 夹爪动作行程输入框（TR-058）：gripperTarget 轴5 绝对目标坐标（0=夹紧、负=松开），执行越界拒绝；旧行为翻转已修（「打开夹爪」=松开）。
